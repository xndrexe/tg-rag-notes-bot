# Архитектура

```
┌────────────┐    PDF/DOCX/MD     ┌──────────────┐
│  Telegram  │ ────────────────▶  │  aiogram 3   │
│   client   │                    │   handlers   │
└────────────┘ ◀──── ответы ───── └──────┬───────┘
                                          │
            ┌─────────────────────────────┴─────────────────────┐
            │                                                    │
            ▼                                                    ▼
   ┌────────────────┐                              ┌──────────────────────────┐
   │  extractors    │ ──текст──▶  chunk_text  ──▶  │  store.VectorStore       │
   │  (pypdf/docx)  │             (slidingwin)     │  ─ SQLite + numpy        │
   └────────────────┘                              │  ─ per-user изоляция     │
                                                   │  ─ brute-force cosine    │
                                                   └──────────┬───────────────┘
                                                              │
                                              top_k chunks    │
                                                              ▼
                                                   ┌──────────────────────────┐
                                                   │  answerer.assemble_*     │
                                                   │  ─ extractive (no LLM)   │
                                                   │  ─ llm (OpenAI optional) │
                                                   └──────────────────────────┘
```

## Слои

- **bot.py** — хендлеры aiogram 3: `/start`, `/help`, `/list`, `/forget`,
  приём документа, приём текстового вопроса. Никакой бизнес-логики
  внутри хендлера — только маршрутизация в нижние слои.
- **extractors.py** — извлечение текста из PDF (pypdf), DOCX (python-docx),
  Markdown/txt (read_text). Чанкование по абзацам с overlap для длинных.
- **store.py** — SQLite + numpy. Чанки в таблице с колонкой `user_id`
  для изоляции пользователей. Embedding хранится как BLOB (float32 LE).
  Поиск — brute-force cosine в памяти после загрузки векторов пользователя.
  Для личного бота (тысячи-десятки тысяч чанков) это быстрее и проще
  чем подключать отдельную векторную БД. Дедуп по sha1 содержимого.
- **embeddings.py** — sentence-transformers с ленивой загрузкой модели
  (5-10 секунд первой инициализации не блокируют старт бота).
- **answerer.py** — сборка ответа. Без LLM возвращает цитаты, с LLM
  вызывает OpenAI-совместимый chat completions. Любая ошибка LLM
  откатывает на extractive — пользователь не остаётся без ответа.

## Изоляция пользователей

Все фрагменты лежат в одной таблице SQLite с колонкой `user_id`, поиск
идёт только по строкам пользователя — пересечений данных нет. `/forget`
удаляет конкретный документ владельца, не задевая других пользователей.

## Что осознанно НЕ сделано

- **Один процесс, один бот.** Никакого шардирования, очередей, БД-кластеров.
  Подходит для личного использования и небольших команд (до ~100 активных
  пользователей).
- **Без шифрования содержимого** на диске. Документы лежат в `./data/docs/`
  открытым текстом. Если нужна приватность — поднимайте на машине, к которой
  у вас есть полный доступ.
- **Без авторизации**. Кто угодно может писать боту. Для приватного
  использования — задайте `BOT_TOKEN` приватного бота и не делитесь им.
- **Без долгосрочного отслеживания изменений**. Если документ обновился —
  залейте новый и удалите старый через `/forget`. Автоматического версионирования
  нет.
- **OpenAI fallback, не основной режим**. RAG работает локально на CPU
  через MiniLM-эмбеддинги. OpenAI подключается только для генеративной
  сборки ответа из найденных чанков.
